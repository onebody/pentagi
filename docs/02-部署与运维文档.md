# PentAGI 部署与运维文档

本文给出从零部署到上线运维的完整流程，覆盖：系统配置要求、依赖安装、环境变量、数据库初始化、启动/升级/备份/安全基线。

如需先了解系统功能与使用方式，见 [01-功能清单与操作手册.md](01-功能清单与操作手册.md)。

## 1. 部署形态选择

PentAGI 推荐以 Docker Compose 自托管（官方默认方案），也支持本地开发模式（前后端分离启动）。

- 生产/测试环境（推荐）：Docker Compose
- 开发/二开：本地启动（Go + Node.js），或仍使用 Compose 仅启动依赖（Postgres 等）

## 2. 系统配置要求

### 2.1 基础要求

- 操作系统：Linux（推荐）/ macOS（开发）、Windows（开发）
- 容器运行时：Docker Engine + Docker Compose v2
- 硬件建议：
  - CPU：4C+（推荐 8C+）
  - 内存：8GB+（推荐 16GB+，使用本地大模型/多 Flow 并发时更高）
  - 磁盘：20GB+（日志/截图/数据库会增长）

### 2.2 网络与安全前置

- 默认仅绑定 `127.0.0.1`（本机访问），若需要对外提供服务，务必：
  - 配置正式 TLS（或放到反向代理后）
  - 收敛 `CORS_ORIGINS` 与防火墙规则
  - 修改所有默认口令/盐值（见 4.3）

## 3. 依赖安装步骤（Docker Compose 方案）

### 3.1 安装 Docker / Compose

按官方文档安装 Docker Engine 与 Compose v2。安装完成后验证：

```bash
docker version
docker compose version
```

### 3.2 获取部署文件

你可以直接使用本仓库的 compose 文件，或从 README 指引下载：

- 主栈：`docker-compose.yml`
- 可选栈：
  - Langfuse：`docker-compose-langfuse.yml`
  - Observability：`docker-compose-observability.yml`
  - Graphiti：`docker-compose-graphiti.yml`

## 4. 环境变量与配置（.env）

PentAGI 配置以环境变量为主，后端使用 `godotenv` 自动加载 `.env`（见 [config.go](../backend/pkg/config/config.go#L18-L53) 与 [config.md](../backend/docs/config.md)）。

### 4.1 创建 .env

从示例复制：

```bash
cp .env.example .env
```

### 4.2 最小可运行配置（推荐最小集）

至少需要：

- 数据库（Compose 内 pgvector 默认已提供）：
  - `PENTAGI_POSTGRES_USER`
  - `PENTAGI_POSTGRES_PASSWORD`
  - `PENTAGI_POSTGRES_DB`
- Web 访问：
  - `PENTAGI_LISTEN_IP`（默认 127.0.0.1）
  - `PENTAGI_LISTEN_PORT`（默认 8443）
  - `PUBLIC_URL`（必须与实际访问 URL 一致）
- 认证/会话安全：
  - `COOKIE_SIGNING_SALT`（必须改为高熵随机值；见 4.3）
- LLM Provider（至少一个）：
  - `OPEN_AI_KEY` 或 `ANTHROPIC_API_KEY` 或 `GEMINI_API_KEY` 或 `OLLAMA_SERVER_URL`/`LLM_SERVER_URL` 等

### 4.3 安全相关配置（上线前必须检查）

基于项目默认提示（见 [README](../README.md#L730-L748)）与后端鉴权实现：

- `COOKIE_SIGNING_SALT`
  - 禁止使用空值或示例值（如 `salt`）
  - 推荐长度 32+、随机生成（例如使用密码管理器生成）
- 默认管理员账号口令
  - 首次登录后立即修改（默认值见 [README](../README.md#L763-L763)）
- `PUBLIC_URL` 与 `CORS_ORIGINS`
  - 仅允许实际使用的域名/端口，避免 `*`
- TLS
  - 生产环境推荐使用正式证书（或由反向代理终止 TLS）
  - 自签证书仅用于本地/测试

### 4.4 常用配置片段（示例）

本机访问（默认）：

```env
PENTAGI_LISTEN_IP=127.0.0.1
PENTAGI_LISTEN_PORT=8443
PUBLIC_URL=https://localhost:8443
CORS_ORIGINS=https://localhost:8443
SERVER_PORT=8443
SERVER_USE_SSL=true
COOKIE_SIGNING_SALT=<replace-with-random>
```

局域网访问（示例）：

```env
PENTAGI_LISTEN_IP=0.0.0.0
PENTAGI_LISTEN_PORT=8443
PUBLIC_URL=https://192.168.1.100:8443
CORS_ORIGINS=https://localhost:8443,https://192.168.1.100:8443
SERVER_PORT=8443
SERVER_USE_SSL=true
COOKIE_SIGNING_SALT=<replace-with-random>
```

说明：

- `SERVER_PORT`/`SERVER_USE_SSL` 是后端 Go 服务监听参数；容器端口映射在 [docker-compose.yml](../docker-compose.yml#L25-L34)。
- 若启用 `SERVER_USE_SSL=true` 且未提供证书，容器入口脚本会生成自签证书（见 [entrypoint.sh](../scripts/entrypoint.sh#L16-L54)）。

## 5. 数据库初始化与迁移

### 5.1 pgvector 初始化

Compose 中的 `pgvector` 服务会根据 `POSTGRES_*` 环境变量初始化数据目录与库（卷 `pentagi-postgres-data`）。

### 5.2 应用侧迁移（自动执行）

后端启动时会对 `DATABASE_URL` 指向的库执行 goose migrations（见 [main.go](../backend/cmd/pentagi/main.go#L94-L105) 与 [migrations.go](../backend/migrations/migrations.go)）。

因此“正常启动一次”即完成初始化；无需手动跑迁移命令。

## 6. 服务启动流程（Docker Compose）

### 6.1 仅主栈启动

在项目根目录（含 `.env` 与 `docker-compose.yml`）执行：

```bash
docker compose up -d
```

访问：`https://localhost:8443`（默认）

### 6.2 叠加可选栈

- Langfuse：

```bash
docker compose -f docker-compose.yml -f docker-compose-langfuse.yml up -d
```

- Observability：

```bash
docker compose -f docker-compose.yml -f docker-compose-observability.yml up -d
```

- Graphiti：

```bash
docker compose -f docker-compose.yml -f docker-compose-graphiti.yml up -d
```

全部叠加（按需）：

```bash
docker compose \
  -f docker-compose.yml \
  -f docker-compose-langfuse.yml \
  -f docker-compose-graphiti.yml \
  -f docker-compose-observability.yml \
  up -d
```

注意：网络 `pentagi-network` 等在首次启动主栈时创建；建议先跑一次主栈再叠加（见 [README](../README.md#L765-L766)）。

## 7. 本地开发模式（可选）

适用于二开调试。推荐做法：

- 使用 Compose 启动数据库与依赖（pgvector/scraper 等）
- 本地启动后端（Go）与前端（Vite）并通过代理联调

参考入口：

- 后端：`backend/cmd/pentagi/main.go`
- 前端：`frontend/`（Vite dev server 配置见 `frontend/vite.config.ts`）

## 8. 运维操作

### 8.1 停止与重启

```bash
docker compose down
docker compose up -d
```

### 8.2 升级

典型流程：

1) 拉取新镜像（或更新仓库/compose 文件）
2) `docker compose pull`
3) `docker compose up -d --force-recreate`
4) 观察日志并验证功能

### 8.3 备份与恢复（建议）

需要长期保留的数据主要是：

- Postgres 卷：`pentagi-postgres-data`
- PentAGI 数据卷：`pentagi-data`、`pentagi-ssl`（证书）、`pentagi-ollama`（如使用）

建议至少对 Postgres 做定期导出（逻辑备份）+ 卷级快照（二选一或同时）。

### 8.4 日志与排障

常见排障点：

- DB 连接/迁移失败：检查 `DATABASE_URL`、pgvector 健康状态
- scraper 不可用：检查 `SCRAPER_PRIVATE_URL`、scraper 容器状态与证书
- 无法创建任务容器：检查 Docker 权限与 `docker.sock` 挂载

## 9. 生产安全基线（上线检查清单）

- 必须改：默认管理员密码、`COOKIE_SIGNING_SALT`
- 必须收敛：`CORS_ORIGINS`、对外暴露端口、防火墙策略
- 推荐：将 Swagger/Playground 等开发接口在生产关闭或加访问控制
- 推荐：在反向代理层补齐安全响应头与速率限制（登录、GraphQL 等）
